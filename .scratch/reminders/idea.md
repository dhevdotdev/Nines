# Reminders

**Category:** enhancement

**Status:** superseded

**Superseded by:** `spec.md` and the numbered implementation tickets in this directory.

Notification-based reminders for habits — never scoped or started. Deprioritized repeatedly during early development in favor of getting the core tracking experience right first.

Explicit intent: not a dismissible, easy-to-swipe-away notification. Should behave as a strong, persistent reminder — stays until the user actually takes action (completes the habit, or explicitly defers/snoozes it), not something cleared by a stray swipe.

No design decisions made yet: per-habit vs. global reminder times, whether reminders respect the versioned `Schedule` (see `CONTEXT.md`), what "taking action" means for numeric habits, and how the persistent-notification behavior interacts with Android's notification permission model and battery/background-work restrictions are all open.

### Established during grilling

- Reminders are fully opt-in and per-Habit. A Habit has no Reminder until its owner enables one
  and chooses one local reminder time.
- All Habit types participate. Boolean and `AT_LEAST` numeric Reminders resolve when their Target
  is met; an `AT_MOST` numeric Reminder resolves when the user records its value.
- A Reminder is not an Entry. Snooze changes no tracking data; Not today creates the existing
  `SKIPPED` Entry for that date.
- A due notification is ongoing: a swipe alone cannot resolve it, but the user can resolve it
  from the notification or by taking the relevant action in Nines.
- Snooze choices are 15 minutes, 1 hour, 3 hours, and tomorrow. Reminder times follow current
  local time when the user travels.
- Flexible Targets continue prompting on due days until their active Target is met.
- Individual notifications are the default. A global Combine simultaneous reminders preference
  may replace notifications due in the same scheduled minute with a single notification that
  opens Nines; it has no bulk tracking action.
- If notification permission is denied, retain the configured Reminder and show a clear recovery
  state. Do not request blanket battery-optimization exemption; provide optional device-specific
  troubleshooting only if delivery is delayed.
- The reference check of uHabit was for UX only. Its GPL-3.0 source, assets, and implementation
  are not in scope for reuse.
- Boolean notification actions mark the Habit done directly; numeric actions open the existing
  numeric editor. A due alert alerts once, then remains silent while ongoing.
- Tomorrow snooze uses the Habit’s original local reminder time and fires only if it is next due.
  Nines respects Do Not Disturb.
- Archiving cancels active and scheduled Reminders while preserving their configuration; restoring
  resumes them. An unresolved Reminder is restored after device restart with its original date.

## Agent Brief

**Category:** enhancement
**Summary:** Add fully opt-in, Schedule-aware per-Habit reminders with persistent, actionable
notifications.

**Current behavior:**
Habits have versioned Schedules and date-bounded Entries, but no reminder configuration, delivery,
notification permission flow, or notification actions.

**Desired behavior:**
Each Habit can optionally have one local reminder time. Every Habit type is supported. Boolean and
`AT_LEAST` numerical Reminders resolve when the Target is met; an `AT_MOST` numerical Reminder
resolves when the user records that date's value. A due Reminder remains associated with its
original date until the user resolves it, Snoozes it, or chooses Not today. It is never an Entry
itself.

**Key interfaces:**

- Habit reminder configuration — optional one-time-of-day setting; archiving suspends it and
  restoration resumes it.
- Schedule/Target projection — determines whether a Reminder is due and whether it remains
  unresolved. Reminder state must not become Score, Streak, Gap, or an implicit Entry.
- Reminder delivery and restoration — schedule best-effort local-time delivery, recover after
  reboot, and retain unresolved original dates. Do not request exact-alarm or blanket
  battery-optimization exemption.
- Notification and entry actions — boolean Mark done writes the existing `COMPLETED` Entry;
  numerical Log value opens the existing editor; Not today writes the existing `SKIPPED` Entry;
  Snooze changes only reminder state.
- Reminder preferences — default individual ongoing notifications; an optional global preference
  combines Habits due in the same scheduled minute into one notification that opens Nines.

**Acceptance criteria:**

- [ ] A user can opt in to one local-time Reminder per Habit from Habit editing; no notification
      permission is requested until the first enable attempt.
- [ ] Due logic honours Schedule versions, flexible Target progress, current local time, every
      Habit type, archive/restore, and target/action resolution rules above.
- [ ] A due individual notification cannot be resolved by swipe alone, alerts once then remains
      quiet, respects Do Not Disturb, and can be resolved from the notification or app.
- [ ] Snooze offers 15 minutes, 1 hour, 3 hours, and tomorrow; Tomorrow uses the original local
      reminder time and only fires if the Habit is next due.
- [ ] Notification permission denial preserves the reminder configuration and exposes a recovery
      state. Device-specific delivery troubleshooting is optional and does not request blanket
      unrestricted battery access.
- [ ] Individual versus same-minute combined notification behavior is covered, with no bulk
      tracking action in the combined notification.
- [ ] Reboot and process-recreation behavior restores scheduled and unresolved reminders.
- [ ] Pure due/resolution logic has unit tests; Android notification/scheduling integration has
      connected-device verification, including Doze/reboot behavior where practical.

**Out of scope:**

- Multiple reminder times per Habit.
- Exact-alarm access, bypassing Do Not Disturb, or mandatory battery-optimization exemption.
- Bulk Snooze, bulk Not today, or a new skip-day domain model.
- Copying uHabit source, assets, or implementation.
